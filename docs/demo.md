# Демо и защита reqcheck

## Подготовка

- Выполнить инструкции из [README](../README.md). Выбрать доступную модель и проверить запуск на сети, которую будете использовать при записи.
- Установить `REQCHECK_CRITIC_VOTES=1` и прогнать `examples/requirements.md` заранее. Открыть HTML-отчёт и выбрать контрпример симулятора с двумя точными цитатами. Для основного примера подойдёт повторное достижение нового порога в том же месяце.
- Открыть локальное веб-демо. Держать рядом готовый HTML-отчёт и терминал с CLI. Если модель недоступна, показать готовый отчёт с его паспортом и провести короткую проверку правил вживую.

## Сценарий записи на три минуты

| Время | На экране | Реплика |
| --- | --- | --- |
| 0:00–0:25 | Исходная спецификация и два связанных фрагмента | «Разработчик и QA могут понять одно правило по-разному. Агент находит такие места до начала работ». |
| 0:25–1:15 | Загрузка файла, ход этапов, первый экран отчёта | «Загружаю документ. Агент выделяет требования, проверяет формулировки и связи, затем сверяет каждую цитату с источником». |
| 1:15–2:05 | Контрпример, две цитаты и связанный вопрос | «Симулятор берёт один сценарий и применяет оба правила. Получаются два разных результата». Открыть «Источник». В разделе «Вопросы» выбрать связанный вопрос, ввести подготовленный ответ и запустить повторную проверку. |
| 2:05–2:40 | Диаграмма из README и паспорт отчёта | «Правила и модель дают отдельные выводы. Проверка цитат исключает неподтверждённые ссылки. Паспорт показывает профиль запуска и число отброшенных выводов». |
| 2:40–3:00 | Вердикт, первые правки и ссылка на репозиторий | «Аналитик получает порядок исправлений. QA видит, что пока нельзя проверить. В README есть команда для воспроизведения». |

Если показываете метрики, берите числа из `python -m eval.score` для того же отчёта. Рядом с precision укажите число оценённых выводов.

## Слайды для пяти минут

1. **Цена двусмысленности.** Одна пара цитат из спецификации и два возможных результата.
2. **Рабочий прогон.** Загрузка, этапы, критический вывод и вопрос.
3. **Уточнение.** Один ответ владельца, повторная проверка и запись ответа в отчёте.
4. **Архитектура.** Схема агентов, схема JSON и проверка цитат. Показать паспорт с фактическими данными прогона.
5. **Работа аналитика и QA.** Когда запускать проверку и что исправить до приёмки. Показать вердикт и команду запуска.

## Вопросы жюри

- **Как контролируете галлюцинации?** Проверяем дословную цитату по указанному месту. Смысл вывода проверяется отдельно по эталону.
- **Поддерживаются другие документы?** Покажите результат проверки `examples/merchant-settlement.md`. Правила выбора локаторов и проверки общие.
- **Куда попадает закрытый документ?** Текст передаётся настроенному провайдеру. Для закрытых документов команда может указать свой локальный endpoint.
- **Что будет при отказе модели?** Отчёт сохранится. Паспорт покажет режим проверки и этапы без ответа.
