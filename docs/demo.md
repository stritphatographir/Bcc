## Подготовка

- Выполнить инструкции из [README](../README.md). Выбрать доступную модель и проверить запуск на сети, которую будете использовать при записи.
- Для живого показа выбрать `gemini-3.5-flash-lite`, установить `REQCHECK_CRITIC_VOTES=1` и заранее прогнать `examples/requirements.md`. В [финальном отчёте](../reports/report.md) 27 из 30 групп эталона (90,0%), 59 подтверждённых из 71 оценённого вывода (83,1%) и 55 уточняющих вопросов.
- Открыть локальное веб-демо. Держать рядом готовый HTML-отчёт и терминал с CLI. Если модель недоступна, показать готовый отчёт с его паспортом и провести короткую проверку правил вживую.

## Если модель отвечает медленно или отключилось питание

Перед показом распакуйте конкурсный ZIP на заряженном ноутбуке. Откройте
`report.html` и `demo.mp4` с диска при отключённой сети. В HTML можно показать
цитаты и вердикт, а в видео — ввод ответа и перепроверку.

Перед показом настройте основной и резервный серверы по [README](../README.md)
и проверьте оба на коротком документе. Тогда агент сам переключится, если ответ
не укладывается в заданное время. Если оба сервера недоступны или компьютер
выключился, продолжите показ по файлам на ноутбуке.

После перезапуска компьютера повторите команду из той же рабочей папки с тем же
документом и настройками. В Docker храните `.cache/reqcheck`, входной файл и
каталог отчётов на постоянном томе. Агент повторно использует сохранённые ответы
на совпавшие запросы. Незавершённый запрос выполняется заново. Сохраните отдельно
ответы, введённые в форме до выгрузки отчёта. Для повторного запуска укажите новый
путь, например `-o reports/run/recovered.md`.

## Контрпример для живого показа

Покупка совершена 31 января и проведена 1 февраля. По правилу в строке 38
выбирается январь, а приёмочный пример в строке 64 ожидает увеличения февральского
счётчика. В сохранённом отчёте это D-036 и Q-02. В новом прогоне найдите конфликт
по цитатам из строк 38 и 64, откройте его в «Источнике» и перейдите к связанному вопросу.
Учебный ответ: «Месяц определяется по дате исходной операции в часовом поясе
Алматы, даже если обработка произошла в следующем месяце. Исправляем ожидаемый
месяц в критерии приёмки».

Этот путь проверен в Edge. Вопрос содержит строки «Также: …», ответ сохраняется
в интерфейсе и в выгруженном JSON. Перепроверка получила шесть ответов Gemini
и вернула два дополнительных вывода. D-037 показывает ещё один конфликт:
повторное достижение порога после смены настройки в том же месяце.

## Слайды для пяти минут

1. **Цена двусмысленности.** Одна пара цитат из спецификации и два возможных результата.
2. **Рабочий прогон.** Загрузка, этапы, критический вывод и вопрос.
3. **Уточнение.** Один ответ владельца, повторная проверка и запись ответа в отчёте.
4. **Архитектура.** Схема агентов, схема JSON и проверка цитат. Показать паспорт с фактическими данными прогона.
5. **Работа аналитика и QA.** Когда запускать проверку и что исправить до приёмки. Показать вердикт и команду запуска.

## Вопросы жюри

- **Как контролируете галлюцинации?** Проверяем дословную цитату по указанному месту. Смысл вывода проверяется отдельно по эталону.
- **Поддерживаются другие документы?** Покажите результат проверки `examples/merchant-settlement.md`. Правила выбора локаторов и проверки общие.
- **Куда попадает закрытый документ?** Текст передаётся настроенному провайдеру. Для закрытых документов команда может указать свой локальный endpoint.
- **Что будет при отказе модели?** Отчёт сохранится. Агент прекращает обращения после первой фатальной ошибки (нет связи, неверный ключ), паспорт покажет причину, режим проверки и этапы без ответа. На 429 бесплатного тарифа агент ждёт по `Retry-After`.
- **Почему вопросов меньше, чем дефектов?** Несколько критиков могут описать одну проблему разными словами. Clarifier группирует выводы по вопросам и цитатам. В финальном отчёте Gemini 71 вывод и 55 вопросов. Например, Q-02 связан с D-036 и D-024.

## Защита: «агент подогнан под пример?»

Нет. В промптах и коде нет фактов из `examples/requirements.md`. Каждая добавленная проверка — общее структурное правило:

- настраиваемый числовой диапазон, для которого значение по умолчанию задано только у переключателя;
- тип содержимого объявлен в разделе тела запроса, где сказано, что тела нет;
- пример ошибки валидации под заголовком HTTP 2xx при правиле с кодом 4xx;
- признак отправки хранится или меняется, но событие перехода не определено;
- правило отнесения к месяцу противоречит строке приёмки на границе месяцев;
- лимит на период повторяется после перенастройки без учёта истории;
- идентификатор хранится без срока хранения или события удаления.

После каждого принятого изменения второй пример `examples/merchant-settlement.md` давал те же выводы (31–32; в итерации 3 ушёл один дубликат). Изменения промптов без общего эффекта откачены (итерации 2, 5 и 9): в них выводы на втором примере менялись.

На втором документе со списком дефектов, составленным до запуска: слепой recall 6/21, после общих финтех-проверок 17/21 при precision 35/36 (Qwen). Второй результат уже не слепой; это сказано в README.
